# PD-PPO 次优性的系统性诊断：实验合理性评估与解决方案

## 总体框架

当前 PD-PPO 的次优性由四个相互独立但在能量账户场景下同时激活的结构性原因决定。前一版诊断（turn 76）已识别这四个原因，但对其中原因二（预测信息利用不足）和原因四（训练充分性）的优化手段描述较为粗略，且缺乏对各原因实验合理性的系统评估。本文在此基础上进行深化：对每个原因给出更精确的理论定位、评估当前实验设计的合理性与不合理之处，并提出具体的解决方案。

---

## 原因一：目标函数与真实损失之间的系统性错位（Reward Misspecification）

### 理论定位

当前奖励函数 $r_t = -\text{MAE}_t - \lambda \cdot \text{energy\_penalty}_t$ 对所有时间步一视同仁，而评估指标 FW-MAE 对 blowing-snow event 期间的误差赋予更高权重。这在理论上等价于在一个信号噪声比极低的奖励流上做策略优化：非事件期（占主导）的密集低信息奖励系统性地稀释了事件期的梯度贡献。Ibrahim 等人（2024）将此类问题归类为奖励设计的核心陷阱之一——"奖励与真实目标的错位"（Misaligned Reward with True Objective），即奖励函数未能真正激励期望行为 ([Ibrahim et al., 2024](https://ar5iv.labs.arxiv.org/html/2408.10215v1))。

### 实验合理性评估

当前 storm-window curriculum 是对这一问题的**采样层面补丁**：通过重采样提高事件期样本密度，隐式修正了奖励信号的信噪比。这一设计在实验上是合理的——它确实改善了训练效果，且 AWBC+oracle-prior 消融的显著性（p=0.002）证明了预测信息的有效性。

**不合理之处**在于：storm-window curriculum 改变了训练数据分布，但未改变奖励函数本身的权重结构。这意味着策略在非 storm-window 的正常时间步上仍然接收到未加权的奖励信号，导致策略在这些步骤上的行为未被充分优化。更根本的问题是，当前实现中 event 指示变量 $z_t$ 使用模拟器地面真值，而非 TCN oracle 的预测输出，这在训练时引入了一个在部署场景中不可用的信息源，构成训练-部署不一致性。

### 解决方案

最直接的修正是将即时奖励函数改为对事件期步骤显式加权：

$$r_t = -\text{MAE}_t \cdot \left(1 + \alpha \cdot \mathbf{1}[z_t]\right) - \lambda \cdot \text{energy\_penalty}_t$$

其中 $\alpha > 0$ 是事件期权重系数，$\mathbf{1}[z_t]$ 是事件指示变量。Pendyala 等人（2024）在真实工业优化问题中验证了类似思路：针对"重要动作稀少"（important actions being infrequent）的问题，他们设计了 Positional Reward，在每个时间步对所有容器的状态赋予持续的奖励信号，而非仅在稀有的关键动作发生时才给予反馈，从而解决了长时间零奖励导致的梯度传播困难 ([Pendyala et al., 2024](https://ar5iv.labs.arxiv.org/html/2404.02577))。这与当前问题的结构完全对应：非事件期的密集低信息奖励掩盖了事件期的稀疏高价值信号。

在部署场景中，$\mathbf{1}[z_t]$ 需替换为 TCN oracle 的预测输出 $\hat{z}_t$，这引入了额外的预测误差，需在 §3.4 的部署说明中明确。

## 原因二：预测信息在状态空间中未被充分利用（Partial Observability of Forecast Horizon）

### 理论定位

PD-PPO 的核心设计是将 TCN oracle 的多步预测嵌入观测空间，使 agent 能够"预见"即将到来的 blowing-snow 事件，从而提前启动 warm-up。但当前实现存在一个**时序对齐问题**：oracle 预测的时间跨度 $H$ 与 warm-up 延迟 $\tau$ 之间的匹配程度未经优化。

设 warm-up 延迟为 $\tau$ 步，oracle 提供未来 $H$ 步的预测。最优策略需要在 $t - \tau$ 时刻就决定是否启动 warm-up，以便在 $t$ 时刻事件发生时 laser 已就绪。这要求 oracle 在 $t - \tau$ 时刻对 $t$ 时刻的预测足够准确，即要求 $H \geq \tau$。若 $H < \tau$，oracle 根本无法提供足够超前的预警，策略退化为反应式而非预测式；若 $H \gg \tau$，远期预测精度下降，噪声增大，反而干扰决策。

历史诊断中 laser event/non-event ratio ≈ 1.03×（几乎无事件触发分化）是这一问题的直接症状：agent 并未学会利用预测信息提前切换，说明预测信号在当前状态编码方式下**未被有效提取**。

### 实验合理性评估

**不合理之处**在于：当前实验从未系统地测量 $H$ 与 $\tau$ 的实际数值，也未验证二者是否匹配。这是一个**可测量但未被测量的设计参数**，其缺失使得"预测驱动"这一核心设计主张缺乏内部一致性验证。

具体而言，存在以下三个可能的失效模式，当前实验无法区分：

第一，$H < \tau$（预测窗口不足）：oracle 的预测时间跨度不足以覆盖 warm-up 所需的提前量，导致 agent 在收到预测信号时已经来不及启动 warm-up。这种情况下，即使 oracle 预测完全准确，策略也无法利用这一信息。

第二，预测特征在网络中被淹没（Feature Dominance）：oracle 预测特征在高维状态向量中占比较小，网络可能学会忽略这些特征而依赖其他状态维度（如当前 SOC、当前传感器状态）做出决策。EventAwareCritic 消融的不显著性（p=0.846）和 ActionEmbedding 的不显著性（p=0.695）均支持这一解释：这些专门设计用于利用预测信息的模块对最终性能没有显著贡献，说明预测信息在当前架构中确实未被有效利用。

第三，预测误差传播（Prediction Error Propagation）：TCN oracle 的预测误差在多步预测中累积，导致远期预测信号的信噪比过低，agent 学会了忽略这些噪声信号。

### 解决方案

**解决方案一（时序对齐验证）**：在现有实验框架内，测量 warm-up 延迟 $\tau$ 的实际分布（从 warm-up 启动到 laser 就绪的步数），并与 oracle 预测窗口 $H$ 进行比较。若 $H < \tau$，则需要增大预测窗口或减小 warm-up 延迟。这是一个零成本的诊断实验，应在任何架构修改之前完成。

**解决方案二（预测特征显著性测试）**：通过消融实验，将 oracle 预测特征从状态向量中完全移除，观察性能变化。若移除后性能无显著下降，则证明预测信息确实未被利用，需要从架构层面解决特征提取问题。当前消融（EventAwareCritic p=0.846）已经提供了间接证据，但需要更直接的 oracle-feature ablation。

**解决方案三（预测特征工程）**：将 oracle 的多步预测输出转化为更具信息量的特征表示，例如：预测的事件发生概率（而非原始预测值）、预测的事件发生时间（距当前步的步数）、预测置信度（基于历史预测误差的校准）。这些工程化特征比原始预测值更容易被策略网络利用，且对预测误差更鲁棒。

## 原因三：能量约束的处理方式导致策略保守化（Constraint Handling Induces Risk Aversion）

### 理论定位

当前 PPO 通过固定软惩罚系数 $\lambda$ 处理能量约束。软惩罚的理论缺陷是：**惩罚系数 $\lambda$ 的选择在 Lagrangian 对偶意义上等价于对约束违反的风险容忍度，而最优 $\lambda^*$ 需通过对偶上升（dual ascent）动态求解**。固定 $\lambda$ 是对最优对偶解的静态近似，在约束绑定场景下会系统性地偏离最优策略。

Fernández-Bes 等人（2015）在能量收集传感器的 MDP 模型中证明，最优传输策略由一个能量依赖的阈值函数 $\mu(e)$ 决定：当即时奖励超过阈值时传输，否则保留能量。关键结论是，这个阈值函数是电池电量 $e$ 的**递减函数**——电量越高，阈值越低，传输越积极；电量越低，阈值越高，策略越保守（[Fernández-Bes et al., 2015](https://ar5iv.labs.arxiv.org/html/2502.00940v1)）。这意味着最优约束处理策略本质上是**状态依赖的**，而非固定系数的。

当前固定 $\lambda$ 软惩罚相当于用一个常数阈值近似这个状态依赖的阈值函数，在约束绑定场景（B=1.20）下必然导致系统性偏差：在 SOC 较高时过于保守（不必要地抑制 laser 激活），在 SOC 较低时可能不够保守（未能充分保护约束边界）。

Ying 等人（2022）在熵正则化 CMDP 框架下证明，Lagrangian 对偶函数是光滑的，对偶间隙可分解为原始最优性间隙与约束违反量之和，并提出加速对偶下降方法，实现了 $\widetilde{\mathcal{O}}(1/T)$ 的全局收敛率 ([Ying et al., 2022](https://proceedings.mlr.press/v151/ying22a.html))。这意味着动态 $\lambda$ 的 Lagrangian 松弛方法在理论上保证收敛到约束边界附近的最优策略，而固定 $\lambda$ 方法不具备这一保证。

### 实验合理性评估

**合理之处**：在固定预算场景（B=1.70）下，约束实际上是非绑定的（static projection 消耗 1.46，margin=0.24），因此软惩罚对策略的扭曲效应被掩盖，实验结果仍然有效。Fernández-Bes 等人（2015）的 Theorem 1 在此场景下提供了正向理论验证：非绑定约束下，固定子集策略是最优的，这与 PD-PPO 在固定预算场景下退化为准静态行为（sensors=5.4，switches/step=0.337）的实验观察完全一致。

**不合理之处**：在能量账户场景（B=1.20）下，约束是真正绑定的，此时固定 $\lambda$ 的保守化效应直接压制了 laser 的动态激活频率。当前实验未对 $\lambda$ 进行系统性的敏感性分析，也未测量不同 SOC 水平下策略行为的变化，因此无法区分"策略本身次优"与"$\lambda$ 选择不当"这两个原因。这是一个**可控但未被控制的混淆变量**。

### 解决方案

**解决方案一（$\lambda$ 敏感性分析）**：在能量账户场景下，系统性地扫描 $\lambda \in \{0.1, 0.5, 1.0, 2.0, 5.0\}$，观察 abort 次数、laser event ratio 和 storm loss 的变化。这是一个低成本的诊断实验，可以确定当前 $\lambda$ 是否是主要瓶颈。

**解决方案二（SOC auxiliary critic）**：引入 SOC 辅助 critic，将 SOC 状态纳入价值函数估计，使 actor 在接近约束边界时能够获得更准确的风险信号。历史实验结果支持这一方向：SOC auxiliary critic 版本在 storm 场景下将 abort 从 25.8 降至 16，同时 storm loss 从 0.4153 降至 0.4069，证明约束感知的价值函数设计能够同时改善约束满足和目标优化两个维度。这在理论上对应于 Fernández-Bes 等人（2015）的状态依赖阈值函数 $\mu(e)$：SOC critic 相当于为约束代价提供了一个动态估计的影子价格，比固定 $\lambda$ 更接近最优对偶解。

**解决方案三（CMDP 框架重构）**：将传感器调度问题显式建模为约束马尔可夫决策过程（CMDP），通过对偶上升动态求解最优 $\lambda^*$。Kongarana 等人（2026）在预算感知特征选择问题中将 CMDP 框架与 PPO 结合，通过 CPO（Constrained Policy Optimization）算法在不同预算约束（80%/50%/20%）下实现了约束感知的特征选择策略，验证了 CMDP 框架在资源受限传感器调度类问题中的可行性 ([Kongarana et al., 2026](https://openreview.net/pdf/d4acb51043380b9161f2877dfd90cf322c2b67c7.pdf))。

## 原因四：训练长度不足以收敛到策略空间的高质量区域（Sample Efficiency Bottleneck）

### 理论定位

当前 100k 步训练在 storm-window curriculum 下对应的有效事件期样本数量有限。PPO 作为 on-policy 算法，每次策略更新后旧样本即被丢弃，样本效率本身就低于 off-policy 方法。更关键的是，sensor scheduling 问题的状态空间包含 SOC 状态、warm-up 状态、多传感器组合状态，其有效维度随传感器数量指数增长，在 100k 步内 PPO 对这个空间的覆盖是稀疏的，尤其是在 SOC 接近约束边界的高风险区域。

### 实验合理性评估

**合理之处**：历史结果中 300k seed41 的 storm loss 从 0.4106 降至 0.4053，laser event ratio 从 ≈1.03× 提升至 1.52×，直接证明了训练长度的影响：更长训练使策略在约束边界附近的行为发生了质的变化，从保守的固定子集退化转变为真正的事件触发切换。这一实验证据是充分的。

**不合理之处**在于两个层面：

第一，**收敛性未被验证**。当前实验仅报告了 100k 和 300k 两个数据点，但未绘制训练曲线（training curve），因此无法判断 100k 时策略是否已经收敛，还是仍处于快速改善阶段。若训练曲线在 100k 时仍有明显上升趋势，则 100k 的选择是任意的而非合理的。这是一个**应当报告但未报告的诊断信息**。

第二，**on-policy 的样本效率瓶颈未被量化**。PPO 的 on-policy 特性意味着每个样本只被使用一次（或少数几次 epoch），而 off-policy 方法（如 SAC、TD3）通过 replay buffer 可以多次利用历史样本。在 storm-window curriculum 下，有效事件期样本的比例本已较低，on-policy 的低样本效率进一步放大了这一问题。当前实验未与任何 off-policy 基线进行比较，因此无法量化这一瓶颈的实际影响。

### 解决方案

**解决方案一（训练曲线分析）**：绘制 storm loss 和 laser event ratio 随训练步数的变化曲线，确定收敛点。若曲线在 100k 时仍有明显上升趋势，则应将训练延长至收敛（预计 300k–500k 步）。这是一个零成本的诊断，应作为标准实验报告的一部分。

**解决方案二（延长训练至 300k）**：基于 300k seed41 的正向结果，将所有 n=5 seeds 的训练延长至 300k 步，重新评估 storm loss 和 laser event ratio 的分布。这是当前框架内最直接的改进，且有历史证据支持其有效性。

**解决方案三（off-policy 方法）**：将 PPO 替换为 SAC（Soft Actor-Critic）或 TD3，利用 replay buffer 提高样本效率。在 storm-window curriculum 下，off-policy 方法可以多次重用历史事件期样本，从根本上解决样本稀疏问题。这是一个较大的架构变更，适合作为 Future Work 方向，而非当前论文的修改内容。

## 综合评估：四个原因的相互作用与实验设计建议

四个原因在能量账户场景（B=1.20）下**同时激活**，且存在相互放大效应：训练不足（原因四）使得策略无法充分探索约束边界附近的状态空间，而约束处理的保守化（原因三）进一步压缩了有效探索区域，预测信息的未充分利用（原因二）则使策略无法在事件发生前提前调整，奖励信号的稀释（原因一）最终导致梯度估计偏差。这四个原因的叠加效应解释了为什么能量账户场景下 PD-PPO 相对最强静态基线（validation_selected_static）的优势不稳健（仅 2/5 seeds 胜出，均值更差）。

从实验设计的角度，当前论文存在以下**可修复的不合理之处**，按优先级排序：

其一，**$H$ 与 $\tau$ 的对齐验证缺失**（原因二）：这是一个可以在不重新训练的情况下通过代码分析完成的诊断，应在 §3.4 或 §6.6 中明确报告。

其二，**训练曲线缺失**（原因四）：训练曲线是判断 100k 步选择合理性的必要证据，其缺失使得"训练不足"这一诊断缺乏直接支撑。

其三，**$\lambda$ 敏感性分析缺失**（原因三）：在能量账户场景下，$\lambda$ 的选择对策略行为有显著影响，但当前实验未报告 $\lambda$ 的取值及其敏感性，使得"软惩罚导致保守化"这一诊断缺乏量化支撑。

其四，**oracle feature ablation 缺失**（原因二）：当前消融仅测试了 EventAwareCritic 和 ActionEmbedding 的贡献，但未直接测试移除 oracle 预测特征的影响，使得"预测信息未被利用"这一诊断依赖间接证据。

上述四项诊断实验均不需要重新训练主要模型，可以在当前实验框架内以较低成本完成，且每一项都能为论文的 §6.6 机制诊断和 §7 Future Work 提供更坚实的实证基础。

## 对论文叙事的含义

这一系统性诊断支持当前论文的保守主张：**当前 PD-PPO 是一个证明框架可行性的基线，而非该框架的最优实例化**。四个结构性原因中，原因一（奖励错位）和原因三（约束处理）有历史实验结果支撑，可作为 §7 Future Work 中有实证动机的具体方向；原因二（预测信息利用）有消融实验的间接证据，需要补充 oracle feature ablation 加以确认；原因四（训练充分性）有 300k seed41 的直接证据，但需要训练曲线作为补充。

论文的科学诚实性体现在：这四个改进方向（event-weighted objective、预测窗口对齐、SOC-aware CMDP、更长训练）构成了自然的 future work 路线图，且每一项都有当前实验结果作为动机证据，而非凭空提出的改进方向。
