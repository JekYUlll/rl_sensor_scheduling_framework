# Turn 23：v2主线坐实策略与下一步执行计划

## 一、当前状态评估

v2实验已经实现了论文主线所需的核心结构：`full_open_unconstrained`（0.2919）作为上界，PPO（0.4592）在功率约束内优于所有朴素可行基线（random 0.5132、feasible_static_projected 0.5288、AoI 0.5367、round_robin 0.5590）。三项诊断指标均已达标：事件覆盖率30.1%（方案A有效）、约束绑定率94.5%（方案B有效）、最优动作dominant rate仅25.6%（奖励时变性充分）。

**当前唯一的关键缺口**：现有主指标`weighted_normalized_mae`衡量的是"调度后观测序列与真值的贴近程度"（state reconstruction quality），而论文的核心主张是"预测驱动型调度提升下游预测器的预测精度"（forecast quality）。这两个指标在概念上不等价——前者反映传感器覆盖质量，后者反映冻结预测器在不同调度策略下的未来预测误差。若论文Table 2以前者作为主指标，审稿人可能质疑"调度优化的目标是预测还是观测覆盖"，从而动摇核心贡献链的逻辑一致性。

**关于oracle_loss_mean的问题**：静态组合在`oracle_loss_mean`上略优于PPO，这是因为oracle在训练时见过full_open的完整观测，而PPO调度下的部分观测输入会引入信息损失。这一差距在引入真实forecast metric后可能缩小（因为forecast metric直接衡量oracle在PPO调度输入下的预测输出，而非oracle的训练损失）。若差距仍存在，PPO warm-start是合理的下一步。

**结论**：不需要继续增加场景复杂度。当前配置（事件覆盖30%、budget=1.70、均值填充、多起点oracle预训练）已经足够，下一步的唯一任务是**修正评估口径**，使主指标与论文核心主张严格对齐。

## 二、评估口径修正的技术方案

### 2.1 当前指标与目标指标的区别

当前`weighted_normalized_mae`的计算路径：
```
rollout观测序列（含均值填充）→ 与truth对比 → 加权MAE
```

目标`forecast_weighted_mae`的计算路径：
```
rollout观测序列（含均值填充）→ 输入frozen TCN oracle → 预测未来H步 → 与future truth对比 → 加权MAE
```

关键差异：目标指标需要在rollout结束后，用每个时步的`(observations, masks)`重建oracle输入，调用frozen oracle前向推理，计算预测输出与未来真值的误差。这才是论文所声称的"预测驱动型调度"的直接评估。

### 2.2 实现要点

**输入重建**：oracle的输入是lookback窗口内的观测序列（含均值填充）加上传感器状态向量。rollout已经记录了每步的`observations`和`masks`，可以直接重建oracle输入，无需重新运行环境。

**分层报告**：forecast metric应分三层报告：
- `forecast_weighted_mae_overall`：全时段加权MAE（Table 2主指标）
- `forecast_weighted_mae_event`：吹雪事件时段（wind_speed > 8 m/s）的MAE（Table 3逐变量分析）
- `forecast_weighted_mae_low_temp`：低温时段（T < -30°C）的MAE（Table 3分层报告，支撑M4修改项）

**指标重命名**：将现有`weighted_normalized_mae`重命名为`obs_reconstruction_mae`，降级为诊断指标（附录或Section 6.1实验配置说明中保留），不作为Table 2主指标。

### 2.3 PPO warm-start的触发条件

若修正评估口径后，PPO在`forecast_weighted_mae`上仍弱于`feasible_static_projected`，则执行PPO warm-start：
- 用oracle-greedy可行候选（每个状态下，枚举所有可行动作，选择oracle预测误差最小的动作）生成行为克隆数据集
- 先做supervised warm-start（BC loss），再PPO fine-tune
- 这比继续调SB3超参数更有理论依据，且可以在论文Section 5.5中作为"两阶段训练协议"的一部分描述

## 三、给Codex的研究计划Prompt

---

### Codex研究计划Prompt

**背景**：当前v2实验已跑通，主要结果（`weighted_normalized_mae`口径）显示PPO优于所有可行朴素基线。但该指标衡量的是"调度后观测序列与真值的贴近程度"，不是论文核心主张所需的"冻结预测器在不同调度策略下的未来预测误差"。下一步任务是修正评估口径，使主指标与论文逻辑严格对齐。

**当前代码结构**（已知）：
- `src/v2/env.py`：AWSEnv，Gym API，未观测变量均值填充
- `src/v2/oracle.py` / `tcn_oracle.py`：frozen TCN oracle，已训练并保存checkpoint
- `src/v2/rollout.py`：rollout逻辑，记录`observations`、`masks`、`truth`
- `reports/v2_ab_realfix_probe_20260501/budget1p70_seed41/evaluation/v2_eval_overall.csv`：当前评估结果

**任务一（最高优先级）：新增真实forecast metric**

在`EvaluationSuite`（或新建`src/v2/forecast_eval.py`）中实现以下逻辑：

1. 输入：rollout产生的完整轨迹，包含每步的`observations`（shape: `[T, lookback, n_vars]`）、`masks`（shape: `[T, lookback, n_vars]`，1表示已观测，0表示均值填充）、`truth`（shape: `[T+H, n_vars]`，完整真值序列）

2. 对每个时步`t`，构建oracle输入：取`observations[t]`（已含均值填充的lookback窗口），输入frozen TCN oracle，得到预测输出`y_hat[t]`（shape: `[H, n_vars]`）

3. 计算预测误差：`forecast_mae[t, v] = mean(|y_hat[t, :, v] - truth[t+1:t+H+1, v]|)`

4. 加权聚合：`forecast_weighted_mae = mean_t(sum_v(w_v * forecast_mae[t, v]) / sum_v(w_v))`，其中`w_v`与训练时奖励函数中的权重一致

5. 分层报告（必须实现）：
   - `forecast_weighted_mae_overall`：全时段
   - `forecast_weighted_mae_event`：`wind_speed[t] > 8.0`的时步子集
   - `forecast_weighted_mae_low_temp`：`air_temp[t] < -30.0`的时步子集（若当前合成数据中低温时段存在）
   - `forecast_by_variable`：每个变量的未加权MAE（用于Table 3逐变量分析）

6. 将现有`weighted_normalized_mae`重命名为`obs_reconstruction_mae`，保留为诊断指标，不删除

7. 更新`v2_eval_overall.csv`的输出格式，新增上述列；同时输出`v2_eval_by_variable.csv`（每变量forecast MAE）和`v2_eval_by_condition.csv`（分条件forecast MAE）

**验收标准（任务一）**：
- `full_open_unconstrained`的`forecast_weighted_mae_overall`应为所有策略中最低（上界验证）
- PPO的`forecast_weighted_mae_overall`应低于`random`、`round_robin`、`aoi`、`feasible_static_projected`
- 若PPO的`forecast_weighted_mae_overall`高于`feasible_static_projected`，记录差距数值，进入任务二

**任务二（条件触发）：PPO warm-start**

仅在任务一验收后PPO仍弱于`feasible_static_projected`时执行。

1. 生成行为克隆数据集：对训练集中的每个状态`s_t`，枚举所有通过`OnlineSubsetProjector`的可行动作，用frozen oracle计算每个可行动作下的预测误差（即oracle-greedy动作），记录`(s_t, a_greedy_t)`对

2. 实现BC warm-start：在PPO训练开始前，先用`(s_t, a_greedy_t)`数据集做supervised learning（交叉熵loss），训练PPO的actor网络若干步（建议500–1000步），使actor初始化到oracle-greedy策略附近

3. 再执行标准PPO fine-tune（保持现有超参数不变）

4. 对比warm-start前后的`forecast_weighted_mae_overall`，确认warm-start有效

**任务三（任务一完成后）：单seed验证后的正式网格实验**

在`seed=41, budget=1.70`下验证任务一的forecast metric达标后，运行正式网格：

- Budgets: `[1.65, 1.70, 1.75]`（3个budget值）
- 共9组实验，每组输出完整的`v2_eval_overall.csv`、`v2_eval_by_variable.csv`、`v2_eval_by_condition.csv`

**任务四（任务三完成后）：生成论文图表数据**
