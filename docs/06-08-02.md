# 你现在应该改的方向

## 1. 不再把 Antarctic blowing-snow 写成主贡献

投 ESWA 时，南极场景应该是 **case study / benchmark scenario**，而不是论文的主要科学贡献。

建议文章定位改成：

> A prediction-driven intelligent scheduling framework for power-limited heterogeneous sensing systems, evaluated in an Antarctic blowing-snow monitoring case study.

也就是主线变成：

2. 预测驱动调度；

4. 部署约束下的动态传感器选择；

这样 ESWA 审稿人会更容易接受。

## 2. Title 可以保留，但建议略微强化 intelligent system / scheduling

当前题目：

> Prediction-driven reinforcement learning for power-limited sensor scheduling under deployment constraints

这个题目适合 ESWA，比 CRST 更适合。
但还可以优化为：

**Prediction-driven reinforcement learning for deployment-constrained sensor scheduling in power-limited monitoring systems**

**Prediction-driven intelligent sensor scheduling under power and deployment constraints**

## 3. Introduction 需要从“极地应用”前移到“智能调度问题”

现在 Introduction 仍有明显 cold-region monitoring 入口。投 ESWA 时，开头应改成更一般的智能系统问题：

建议结构：

**第 1 段：通用问题**

> Remote monitoring systems often deploy heterogeneous sensors whose combined sensing capacity exceeds the available power budget. The scheduling problem is not only to reduce measurement uncertainty, but to select the channels that are most useful for downstream prediction under latency, switching, and duty constraints.

**第 2 段：已有方法不足**

说明 AoI、covariance、round-robin、static subset、greedy information gain 的问题：它们优化的是 freshness 或 instantaneous uncertainty，不直接优化 future forecast loss。

**第 3 段：本文方法**

PD-PPO：state → channel scores → projection → feasible subset；frozen forecast oracle → reward。

**第 4 段：case study**

Antarctic blowing-snow monitoring is used as a controlled case study because it contains heterogeneous sensors, rare regimes, delayed event channels, and power-limited deployment constraints.

这样比现在更符合 ESWA。

# ESWA 审稿人会重点卡你的地方

## 1. RL 创新性是否足够

ESWA 不会只问“这个系统对南极有没有用”，它会问：

> 这个 PD-PPO 相比普通 PPO、constrained PPO、greedy scheduling、contextual bandit、MPC，有什么方法层面的必要性？

你现在的稿件中有 projection layer、forecast oracle reward、chronological split、static comparator，这些是优点。但还需要把方法贡献说得更像智能系统论文。

建议强化三点：

1. **Forecast-driven reward design**
   你的核心不是 PPO，而是 reward from frozen multi-horizon forecast oracle。

2. **Feasibility projection**
   这比单纯 penalty 更强，因为 action 在执行前已经满足部署约束。

3. **Evaluation protocol**
   oracle fitting、policy learning、static selection、final testing 使用 disjoint chronological partitions，这是防止时间序列泄漏的重要设计。

这三点应该成为 ESWA 版本的主要贡献。

---

## 2. Baseline 仍然不够强

投 CRST 时，AoI、round-robin、static subset 基本够用。
投 ESWA 时，审稿人会期待更强的 AI / optimization baselines。

建议至少补一个或两个：

### 必补 baseline 1：Vanilla PPO

去掉 prediction-driven oracle regularizer / prior / AWBC，只保留普通 PPO + 同样 projection。

目的：证明 PD-PPO 的增益来自 prediction-driven design，而不是 PPO 本身。

### 必补 baseline 2：Greedy forecast oracle scheduler

每一步枚举 feasible masks，选择短期 oracle loss 最低的 action。

即使它算力高、不适合部署，也可以作为强启发式基线。

### 可选 baseline 3：Contextual bandit

无 long-term credit assignment，只根据当前状态选 sensor subset。
这个 baseline 可以帮助证明 latency、duty、state carry-over 需要 RL。

### 可选 baseline 4：Constrained random / constrained greedy

用于证明 projection + deployment constraints 下的策略选择确实有效。

如果时间有限，优先补：

> Vanilla PPO + Greedy forecast oracle scheduler

这两个对 ESWA 最关键。

---

## 3. deployment-constrained 主实验 5 seeds 仍偏少

ESWA 审稿人对实验统计也会比较敏感。你现在 Table 3 是全文最重要结果，但只有 5 seeds。

建议：

* deployment-constrained 扩展到 10 seeds；
* 与 fixed-budget Table 4 保持一致；
* 报告 mean ± std；
* 做 paired Wilcoxon 或 paired t-test；
* 加 effect size；
* 不要只给 win count。

尤其现在 PD-PPO 相比 deployable static 的平均优势只有 +0.001007，这个差距偏小。如果只保留 5 seeds，ESWA 审稿人可能会认为结果不稳。

---

## 4. Oracle validation 比 CRST 更重要

ESWA 下，frozen oracle 是你的智能系统核心组件。它不再只是辅助评价器，而是 reward generator + evaluator。

必须补：

* oracle architecture；
* training details；
* full-observation forecasting performance；
* target-wise MAE；
* event vs non-event performance；
* oracle sensitivity to missing masks；
* persistence / simple TCN / LSTM 对比。

否则审稿人会认为：

> scheduler is optimized against a black-box evaluator whose reliability is not sufficiently validated.

这是 ESWA 版本最大的技术风险之一。

# Abstract 应该怎样改

现在摘要偏“传感器部署 + 南极应用”。ESWA 版可以这样改主线：

> Power-limited monitoring systems require intelligent scheduling policies that select heterogeneous sensor channels under activation latency, switching, dwell, and duty constraints. Existing scheduling rules based on age of information or instantaneous uncertainty do not directly optimize downstream prediction quality. This study proposes prediction-driven proximal policy optimisation (PD-PPO), a reinforcement-learning scheduler that uses estimator state, sensor freshness, previous actions, budget state, and event context to select feasible sensor subsets. A projection layer enforces deployment constraints, and a frozen multi-horizon forecast oracle supplies the training reward. Oracle fitting, policy learning, static-comparator selection, and final testing are separated by chronological partitions. The framework is evaluated in a controlled Antarctic blowing-snow monitoring case study with heterogeneous microclimate and snow-transport sensors...

后面接结果即可。

关键变化是：**先讲智能调度系统，再讲南极案例**。

# Discussion 也要改

CRST 版 Discussion 重点是 simulation-to-field。
ESWA 版 Discussion 应该重点讨论：

## 1. 什么时候 adaptive RL 有价值

你的结果已经显示：

* fixed instantaneous budget 下 static subset 很强；
* deployment constraints 加入后，PD-PPO 更有优势；
* energy-account 下 event-time activation 更有意义。

这其实是很好的 ESWA 讨论点：

> Adaptive RL scheduling is most useful when the resource model contains temporal coupling: activation latency, duty limits, dwell constraints, energy storage, or event-dependent channel value.

这比单纯说“PD-PPO 更好”更有深度。

## 2. 什么时候 static policy 更好

也要明确：

> When a compact always-on subset is feasible and explains most target variance, static allocation can be a strong and simpler engineering choice.

这会让文章更可信。

## 3. 方法局限

ESWA 版局限应包括：

* simulator-only evidence；
* oracle bias；
* no real hardware power profile；
* limited number of seeds；
* PPO computational cost；
* field event proxy not yet implemented。

# 投稿 ESWA 的最终风险排序

按严重程度：

1. **缺少强 AI baselines**
   尤其 vanilla PPO、greedy oracle、contextual bandit。

2. **oracle 缺少验证**
   frozen forecast oracle 是方法中心，必须证明它可靠。

3. **deployment-constrained seeds 太少**
   主结果 5 seeds 不够稳。

4. **算法贡献表述不够集中**
   需要把贡献从“南极传感器调度”重写为“prediction-driven constrained intelligent scheduling”。

5. **数据与代码可复现性不足**
   ESWA 对应用型智能系统也会关注 reproducibility。Data Availability 里最好承诺公开 generator、configs、evaluation scripts。
