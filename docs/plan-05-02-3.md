- 问题在于当前 SB3 标准离散 PPO 的策略结构不适合候选动作集合调度问题：
  - 动作空间是"从 N 个传感器中选 k 个"的组合空间，候选动作数量随 N 指数增长
  - SB3 PPO 把所有候选动作视为独立类别，无法利用动作之间的结构（哪些传感器被选中）
  - 没有 action mask 机制，策略会在不可行动作上浪费梯度
  - 普通 actor-critic 的 value 估计对稀疏奖励信号（吹雪事件仅占 30%）不稳定
- 继续调超参数（熵系数、步数）无法解决结构性问题

**下一步**：结构性修复——自定义 actor-critic，显式 action mask + 候选动作 embedding + advantage-weighted BC 辅助损失。

**根因分析：为什么当前 SB3 PPO 失效**

当前动作空间是"从 9 个传感器中选 ≤4 个满足功耗约束的子集"，候选动作数量约为 C(9,0)+C(9,1)+...+C(9,4) 量级（经 OnlineSubsetProjector 过滤后约 20–50 个可行动作）。

SB3 标准离散 PPO 的问题：

1. **无 action mask**：策略网络对所有候选动作（包括不可行动作）输出 logit，不可行动作的梯度污染策略更新。虽然 OnlineSubsetProjector 在执行时会过滤，但训练时策略仍在学习不可行动作的概率分布。

2. **无结构感知**：动作被视为独立类别（one-hot），策略无法利用"动作 A 和动作 B 都包含传感器 X"这类结构信息。候选动作之间的相似性完全被忽略。

3. **稀疏奖励下 value 估计不稳定**：吹雪事件仅占 30% 时步，大多数时步奖励信号弱，advantage 估计方差大，策略梯度噪声高。

4. **BC warm-start 与 PPO 目标冲突**：BC 用交叉熵 loss 最大化 oracle-greedy 动作的概率，但 PPO 的 clipped surrogate objective 会在 fine-tune 阶段把策略拉离 BC 初始化点，导致 warm-start 效果消失。

**任务：实现自定义 actor-critic（`src/v2/custom_ppo.py`）**

**核心设计**：

1. **显式 action mask**：在每个时步，`OnlineSubsetProjector` 返回可行动作集合 `A_feasible`，actor 只在可行动作上计算 softmax（masked softmax），不可行动作的 logit 设为 `-inf`。

2. **候选动作 embedding**：每个候选动作表示为其包含的传感器集合的 embedding 之和（set embedding），而非 one-hot。传感器 embedding 维度建议 16–32。这样结构相似的动作（共享传感器）在 embedding 空间中距离更近。

3. **Advantage-weighted BC 辅助损失**：在 PPO 更新中，同时计算 oracle-greedy 动作的 BC loss，但用 advantage 加权：`L_awbc = -advantage * log_prob(a_greedy)`。当 advantage > 0 时，BC loss 强化 oracle-greedy 动作；当 advantage < 0 时，BC loss 弱化该动作。这避免了 BC 与 PPO 目标的冲突。

4. **事件感知 value 网络**：在 value 网络输入中加入"当前是否处于吹雪事件"的二值特征（wind_speed > 8 m/s），帮助 critic 区分高奖励时步和低奖励时步，降低 advantage 估计方差。
