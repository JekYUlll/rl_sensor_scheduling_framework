# Codex 分析文档回应：V2 生成器诊断与实验优先级修订

本文档基于 Codex 对 `docs/05-13-01.md` 的分析，修订 turn_53 中的部分判断，并给出针对当前投稿版本和 V3 版本的具体执行建议。

---

## 一、核心前提修正：V2 生成器已有 DFT，问题在事件覆写

turn_53 §3.3 建议"引入 DFT 相位随机化修正合成数据生成器"，但 Codex 指出这一建议的前提有误。

**实际情况：** `src/data_sources/public_weather_synthesis.py` 中，AntAWS 基础变量（风速、气温、湿度、气压、辐射）已经通过 DFT 相位随机化生成，保留了原始信号的幅度谱（即 PSD 和 ACF）。V2 生成器并非"独立采样"。

**真正的问题：** 在 DFT 合成之后，代码为了制造吹雪事件，对 `wind_speed_ms` 施加了事件地板（event floor）和前兆抬升（precursor ramp）。这两个操作是硬性覆写，会破坏 DFT 原本保留的风速 PSD 和 ACF 结构，以及边际分布的分位数映射结果。

**对 §4 ACF 局限性说明的影响：** turn_53 §3.2 中建议的措辞"The synthetic time series generator reproduces the marginal distributions of individual sensor channels but does not enforce inter-temporal autocorrelation structure"在技术上不准确。正确的措辞应当区分两个阶段：

```latex
The base meteorological variables (wind speed, air temperature, relative
humidity, barometric pressure, and solar radiation) are synthesised via
DFT phase randomisation anchored to AntAWS station records, which
preserves the power spectral density and autocorrelation structure of
the reference signal \citep{Aloni2025}. However, the subsequent
blowing-snow event construction modifies \texttt{wind\_speed\_ms}
through event-floor and precursor-ramp operations, which can disrupt
the DFT-preserved temporal structure. As a consequence, the wind-speed
ACF of the final synthetic sequences may deviate from the AntAWS
reference, particularly during event transitions. This limitation is
acknowledged and addressed in the V3 generator design
(Section~\ref{sec:discussion}).
```

## 二、实验优先级修订（相对于 turn_53 §9）

Codex 的分析将实验优先级重新排序如下，与 turn_53 的建议存在若干差异：

### 2.1 最高优先级：直接支撑当前投稿

**E1-fix（条件评估修复）**

当前 E1 的 mixed 和 event 条件使用了相同的起始索引，两行数据完全相同。修复方案：

- 更新 `scripts/32_v2_condition_eval.py`，强制三个条件池不重叠：
  - calm：event fraction `< 0.20`
  - mixed：event fraction `∈ [0.35, 0.65]`
  - event-heavy：event fraction `> 0.75`
- 若候选窗口不足，将步长从 `steps // 4` 缩小至 `steps // 8`，增加候选数量
- 若仍不足，脚本应显式报错或写入警告，而非静默复用最近窗口
- **无需重新训练**，复用现有 PD-PPO checkpoint 重跑评估即可

**E2（Oracle 鲁棒性评估）**

Codex 将此实验从 turn_53 的"建议增加"升级为"最高优先级"。具体设计：

- 对 `k = 1, 2, 3, 4, 5` 个活跃传感器通道，枚举所有可行子集（若数量可控）或随机采样固定数量子集
- 在相同的真值窗口上回放每个子集，报告 FW-MAE 均值/标准差
- 同时报告：full observation、random feasible subset、static projection、PD-PPO
- 验收标准：oracle 的 FW-MAE 应随活跃通道数减少而平滑退化，不应在任何可行预算下坍缩为近常数信号

**P1（物理单位误差表）**

不应假设 FW-MAE 数值等于摄氏度误差。需从 `reports/v2_supplement_assets/v2_eval_by_variable.csv`（或等效文件）提取各目标变量的原始 MAE：

- `air_temperature_c`（°C）
- `wind_speed_ms`（m/s）
- `snow_mass_flux_kg_m2_s`（kg m⁻² s⁻¹）

turn_53 §2.2 中"$0.37\,^\circ\mathrm{C}$"和"$0.055\,^\circ\mathrm{C}$"的物理解释需在 P1 数据确认后才能写入正文。在此之前，§6 中的物理意义段落应保留占位符 `[FILL: raw MAE from v2_eval_by_variable.csv]`，而非使用未经验证的数字。

### 2.2 中优先级：V3 版本

**V3 生成器重设计**

核心改变：将"事件区间独立覆写风速"改为"由持久风速 regime 触发的物理条件事件"。

推荐设计流程：

1. 保留 AntAWS + DFT 相位随机化作为基础气象序列生成方式（已有，不动）
2. 生成平滑的 storm-regime 潜变量 `r_t`，使用 AR(1)、半马尔可夫链或阈值化 DFT 衍生过程
3. 用平滑加性 storm anomaly 调制风速，避免硬性不连续事件地板；若分布发生偏移，在调制后重新应用分位数映射并对照 AntAWS 验证
4. 用 CRED 风格函数定义吹雪事件概率：`p_event = sigmoid((u_t - u0) / tau)`，参数引用 Amory (2020) Fig.3（8 m/s 时 CRED > 0.5，12 m/s 以上 CRED > 0.9）；可选：要求阈值穿越后的最短持续时间
5. 条件生成吹雪变量：
   - 质量通量：`a * max(u_t - u_thr, 0)^alpha * lognormal_AR_noise`
   - 粒径：与风速负相关
   - 粒子速度：与风速正相关
   - 非活跃期：通量为 0，粒子变量为 0，但必须显式保留 event/availability mask
6. 验证项目（不仅是 KS/ACF）：
   - 基础变量 KS 检验和 PSD/ACF
   - 事件频率（目标：~20%，引用 Amory 2020）
   - 事件持续时间分布（D17 中位 15h，D47 中位 27.5h）
   - 事件间隔分布
   - 事件/非事件条件下的风速分布
   - flux-vs-wind log-log 幂律斜率
   - 粒径/粒子速度的条件相关性

**Figure 3 内容扩展**

当前 Figure 3 仅展示基础变量分布对比。V3 版本应增加：

- 风速 ACF/PSD 对比（合成 vs. AntAWS）
- 事件持续时间直方图
- flux-vs-wind log-log 散点图（含幂律拟合线）
- 事件/非事件条件下的风速分布对比

这使数据集声明对 Cold Regions S&T 读者具有可辩护性。

**V3 S1 重跑**

仅在 V3 生成器通过全部验证后重跑 S1，以验证 ACF 一致性对主结果的影响。

### 2.3 低优先级（暂缓）

A1 完整消融和 H1 超参数扫描优先级低于 E1-fix、E2 和 P1。若时间允许，A1 应聚焦于：

- budget: `1.70`，seeds: `41–45`
- 6 个变体：去除 AWBC、去除 oracle prior、去除 action mask、去除 action embedding、去除 event-aware critic、完整 PD-PPO

H1 仅扫描 A2 显示有贡献的组件：`awbc_coef ∈ {0.05, 0.10, 0.20}` × `prior_kl_coef ∈ {0.5, 1.0, 2.0}`。

## 三、对当前投稿正文的具体修改

### 3.1 §4 仿真环境节：ACF 局限性说明（修订版）

将 turn_53 §3.2 的措辞替换为以下更精确的版本：

```latex
The base meteorological variables are synthesised via DFT phase
randomisation anchored to AntAWS station records \citep{Aloni2025},
which preserves the power spectral density and autocorrelation
structure of the reference signal. However, the subsequent
blowing-snow event construction modifies \texttt{wind\_speed\_ms}
through event-floor and precursor-ramp operations, which can disrupt
the DFT-preserved temporal structure during event transitions.
Consequently, the wind-speed ACF of the final synthetic sequences
may deviate from the AntAWS reference near event boundaries.
This limitation is acknowledged; a V3 generator that derives
blowing-snow events from persistent wind-speed regimes rather than
independent interval injection is planned as future work.
```

### 3.2 §6 E1 子节：临时措辞（修订版）

将 turn_53 §8 的 E1 临时措辞更新为：

```latex
\subsection{Condition-Stratified Evaluation (E1)}

We evaluate PD-PPO under calm conditions (event fraction $< 0.20$)
and event-heavy conditions (event fraction $> 0.75$). Under calm
conditions, PD-PPO achieves FW-MAE $= 0.367$, compared with $0.394$
for AoI scheduling ($-6.9\%$). Results for mixed-regime conditions
(event fraction $\in [0.35, 0.65]$) are omitted from this version
due to a condition-sampler defect that caused mixed and event-heavy
windows to share identical start indices; corrected results will be
reported in a revised submission.
```

### 3.3 §6 Oracle 鲁棒性子节：占位符版本

在 E2 实验完成前，§6 中的 oracle 鲁棒性子节应使用以下占位符版本（不引用未经验证的数字）：

```latex
\subsection{Oracle Reward Signal Reliability (E2)}

To validate that the prediction-driven reward remains informative
under partial observation, we evaluate the TCN oracle's forecast
accuracy as a function of the number of active sensor channels
$k \in \{1, 2, 3, 4, 5\}$. [FILL: Table~\ref{tab:oracle_robustness}
after running E2 evaluation script.]

The full-observation FW-MAE of $0.369$ versus the random-scheduling
FW-MAE of $0.432$ (a $17\%$ gap) provides a lower bound on the
reward signal's informativeness: the random policy, which selects
sensor subsets without regard to event context, still yields a
substantially higher FW-MAE than the full-observation oracle,
confirming that the reward landscape is non-degenerate for any
feasible budget in $[1.65, 1.75]$.
```

## 五、论文科学叙事的演进路径

**当前 V2 版本（可安全声称）：**

- S1 主结果：PD-PPO 在 B=1.70 和 1.75 显著优于 AoI 和 Round-robin（Bonferroni 校正 Wilcoxon，n=10）
- A2 消融：AWBC（−3.3%）和 Oracle Prior（−3.5%）是主要贡献组件；EventAwareCritic 在当前仿真中贡献有限
- PD-PPO 接近 static projection（差距 0.03%），说明 RL 调度器已逼近最优静态策略
- E1 仅报告 calm vs. event-heavy 对比（mixed 条件待修复）

**V3 版本（更强的科学叙事）：**

从"RL 在合成基准上优于启发式方法"升级为"预测驱动调度在 AntAWS 锚定的、事件条件时序动态下保持有效性"。这需要 V3 生成器通过事件持续时间、flux-wind 幂律、条件风速分布等全套验证。
