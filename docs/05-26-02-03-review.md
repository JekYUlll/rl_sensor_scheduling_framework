# 05-26-02/03 合理性审查

## 结论

`05-26-02.md` 和 `05-26-03.md` 的总体判断是合理的：当前
PD-PPO 不是优化路线的最优版本，主要受奖励/评估错位、能量约束处理、
训练样本效率和机制诊断不足限制。它们适合作为内部问题定位和
future-work 路线图。

但两份文档不能直接作为论文论证文本使用。需要降级和修正几处表述，
否则会引入新的证据风险。

## 需要修正的关键点

1. **“TCN oracle 预测嵌入状态空间”不符合当前代码。**
   当前 `src/v2/env.py::WarmupSchedulingEnv._state()` 的 PPO 状态包含历史观测、
   mask history、传感器 warm-up 状态、freshness、上一动作、当前 event flag、
   diurnal phase 和 SOC；没有显式加入 TCN oracle 的多步预测输出。
   TCN oracle 主要作为 frozen forecast-loss reward 使用。

2. **`H` 与 `tau` 的时序对齐批评需要改写。**
   当前 energy-account 配置中 oracle horizon 默认为 `8`，最大 warm-up
   是 laser disdrometer 的 `3` 步，truth generator 的 precursor/lead 是 `5` 步。
   因此“`H < tau` 导致根本来不及预警”不是当前最可能的失效模式。
   更准确的说法是：策略缺少显式未来事件概率/到达时间特征，主要依赖当前
   event flag、历史 wind/observation 轨迹和 reward credit assignment 学习提前启动。

3. **SOC auxiliary 不是完整 CMDP 或独立 Lagrangian critic。**
   当前实现是在 `src/v2/custom_ppo.py` 的 actor-critic 上增加未来 SOC
   prediction head，并以 MSE 作为辅助损失加入 PPO objective。
   它可以被描述为 constraint-awareness auxiliary objective，但不应声称已经实现
   CPO、dual ascent 或严格 CMDP 优化。

4. **文献引用需清理。**
   Ying et al. 2022 的 entropy-regularized CMDP 对偶结果方向相关；
   Pendyala et al. 2024 可支持 curriculum/reward engineering 与稀有关键动作困难。
   Fernandez-Bes 的年份/来源需要校正；文档中的 Kongarana 2026/CPO feature-selection
   引用未核验，不应进入论文，除非换成可查的 primary source。

## 成立的诊断

- Reward/evaluation mismatch 成立：训练即时 reward 与最终 event-weighted
  评价之间仍有错位，event-rich curriculum 只是采样补丁。
- Constraint handling 成立：energy-account 下约束绑定，固定 abort/deficit
  penalty 容易造成保守策略；SOC auxiliary + abort-control gate 是低成本合理试验。
- Sample efficiency 成立：100k 严格协议 baseline 不足以证明 PD-PPO 已收敛；
  当前 200k SOC gate 是合理的下一步，但不是最终算法级解决方案。
- Dynamic-over-static claim 仍未成立：严格协议 n=5 结果只支持 PD-PPO 优于
  AoI/round-robin/random 的弱主张，不支持优于 validation-selected static。

## 修改成本排序

低成本，建议先做：
- 从现有 training history 提取训练曲线和 SOC/abort 轨迹。
- 报告 `horizon=8`、`lead_steps=5`、laser `warmup_steps=3`，修正时序论证。
- 完成当前 `seed=41, 200k, soc_aux=0.1, lambda_warmup_abort=0.16` gate。
- 若 seed-41 同时改善 static comparison 和 abort，再扩到 `n=5`。

中等成本：
- 加入显式事件预测特征，如 future event probability、time-to-event、
  oracle confidence，而不是把原始 TCN forecast 隐含在 reward 中。
- 做 oracle-feature/no-event-context ablation，明确 agent 到底利用了哪些信息。

高成本，当前论文不建议做：
- 完整 CMDP/CPO 或 Lagrangian PPO 重构。
- SAC/TD3/off-policy 替换。
- 大规模 horizon/lambda/architecture 网格。

## 论文边界建议

论文中应把当前 PD-PPO 定位为协议合规的 learned baseline，而不是最优策略。
可保留的主张是：能量账户激活后，动态调度有机制价值；但在严格 split
protocol 下，当前 learned controller 尚未稳定超过训练选择的最强静态基线。
SOC auxiliary 与 abort-control 是正在验证的低成本增强，不应在完成并聚合前进入
main-result claim。
