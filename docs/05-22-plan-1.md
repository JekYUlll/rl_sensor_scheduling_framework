# 调度行为退化诊断与场景调整策略

## 一、根本原因诊断

当前观察到的现象——feasible_static_projected 几乎是固定子集选择（6144步仅11次切换），PD-PPO 也只有 snow_particle_counter 和 laser_disdrometer 两个传感器有动态行为——并非算法失效，而是**环境设计与奖励结构共同导致的"静态陷阱"**。以下从三个层面分析根本原因。

### 1.1 预算约束过于宽松（最核心原因）

当前 B ∈ {1.65, 1.70, 1.75} 的设定意味着：在归一化功率成本体系下，智能体几乎可以在每个时间步同时激活大多数传感器。以 V3.1 的 8 传感器配置为例，若各传感器归一化成本之和约为 8.0（均等假设），则 B=1.70 允许的平均激活比例约为 1.70/8.0 ≈ 21%，即每步约 1.7 个传感器。

**关键问题**：如果 met_station_core、radiometer_basic、snow_particle_counter 三个传感器的成本之和已经接近 B，那么最优静态策略就是"始终开这三个，关其余五个"——这正是 feasible_static_projected 的行为。PD-PPO 学到的也是同样的准静态子集，因为**在宽松预算下，动态切换的边际收益接近零**。

**诊断验证**：检查 met_station_core + radiometer_basic + snow_particle_counter 三个传感器的归一化成本之和是否约等于 B=1.70。若是，则这三个传感器构成了一个"自然最优固定子集"，任何动态调度都无法超越它。

### 1.2 事件频率与预热惩罚不匹配

V3.1 的 semi-Markov 事件结构中，吹雪事件（blowing snow event）触发 laser_disdrometer 和 fc4_flux 的高价值观测窗口。但当前设定下：

- **事件频率偏低**：若事件发生概率 λ_event 较低（如默认 0.3–0.5），则大多数时间步处于非事件状态，此时激活 laser_disdrometer 的边际价值接近零。
- **预热惩罚过重**：laser_disdrometer 和 fc4_flux 有较长的 warm-up latency（τ_w）。若 τ_w 相对于事件持续时间 τ_event 过长，则"预测到事件→激活传感器→等待预热→事件已结束"的情况频繁发生，导致 round_robin 和 AoI 的 warmup_abort_count 极高（分别为 1530 和 2700）。
- **PD-PPO 的理性应对**：PD-PPO 通过 EventAwareCritic 学到了"不值得为短暂事件预热高延迟传感器"，因此将 laser_disdrometer 和 fc4_flux 几乎常关——这是**正确的策略**，但在论文叙事中显得"不够动态"。

### 1.3 β 权重导致吹雪传感器贡献被稀释

FW-MAE 的加权结构中，若 β_snow（吹雪通量权重）相对于 β_meteo（气象变量权重）过低，则即使 laser_disdrometer 和 fc4_flux 的调度决策完全错误，对总体 FW-MAE 的影响也微乎其微。这使得：

- 智能体没有足够的梯度信号去学习吹雪传感器的精细调度
- feasible_static_projected 通过固定开启气象传感器就能获得接近最优的 FW-MAE
- 动态调度的价值被 β 权重结构系统性地低估

## 二、场景调整策略

调整目标是：**在不改变算法核心的前提下，通过修改环境参数，使动态调度的价值在结果中可见**。调整必须有物理合理性依据，不能是为了"让 RL 赢"而人为设计的有利场景。

以下按优先级排列，每项调整均给出具体参数值、物理依据和预期效果。

### 策略 A：收紧预算约束（最高优先级，最直接）

**调整内容**：将主实验预算范围从 B ∈ {1.65, 1.70, 1.75} 扩展为 B ∈ {1.50, 1.55, 1.60, 1.65, 1.70}，并将**论文主结果聚焦在 B ≤ 1.60 的紧预算区间**。

**物理依据**：南极 AWS 的太阳能供电在极夜期间（约 4 个月）完全依赖电池，实际可用功率预算远低于夏季。Parsivel² 加热器激活时功耗高达 50–100 W，在极夜条件下这一成本是决定性的。B=1.60 对应的约束强度更接近真实极夜运行条件。

**预期效果**：
- 在 B=1.50–1.60 时，固定开启三个高成本传感器的策略将违反预算约束，feasible_static_projected 被迫在不同传感器子集间切换
- PD-PPO 的动态调度优势将在紧预算下显现，因为此时"何时激活哪个传感器"的决策具有真实的机会成本
- 预期 PD-PPO vs static projection 的 Wilcoxon 检验在 B=1.50 时达到显著性（p < 0.05）

**实施方式**：
```python
# 修改 V3.1 环境配置
BUDGET_CONFIGS = {
    'tight':    [1.50, 1.55, 1.60],   # 新增：极夜/紧预算场景
    'moderate': [1.65, 1.70, 1.75],   # 保留：原主实验
}
# 论文主表格：展示 tight 区间结果
# 附录：保留 moderate 区间作为对比
```

**注意**：需要同步重新优化 feasible_static_projected 在每个新预算下的最优固定子集（不能沿用 B=1.70 的优化结果）。

### 策略 B：提高吹雪事件频率与持续时间（高优先级）

**调整内容**：将事件频率参数从默认值提升至 2× 基线，同时适当延长事件持续时间。

**物理依据**：Amory (2020) 的 Adélie Land 多年观测数据显示，吹雪事件在冬季的发生频率约为 30–40%（风速 > 8 m/s 的时间占比），而非默认配置中可能使用的较低频率。若当前默认 λ_event 对应约 15–20% 的事件时间占比，则 2× 提升至 30–40% 是有文献支撑的物理合理调整。

**具体参数**：
```python
# 默认配置（当前）
event_config_default = {
    'event_rate': 0.20,          # 事件发生概率（每小时）
    'event_duration_mean': 6,    # 事件平均持续时间（小时）
    'event_duration_std': 2,
}

# 调整后配置（高事件频率场景）
event_config_high = {
    'event_rate': 0.40,          # 2× 基线，对应 Amory 2020 冬季统计
    'event_duration_mean': 8,    # 略延长，给预热留出时间
    'event_duration_std': 3,
}
```

**预期效果**：
- 吹雪传感器（laser_disdrometer, fc4_flux）的激活价值显著提升
- PD-PPO 的 EventAwareCritic 能够更频繁地触发"事件预测→提前激活"的动态行为
- round_robin 和 AoI 的 warmup_abort_count 仍然高（因为它们不预测事件），而 PD-PPO 的预热成功率更高
- 这一场景直接展示了 PD-PPO 相对于非预测性基线的核心优势

**论文定位**：将高事件频率场景定义为"Antarctic winter blizzard-prone conditions"，有 Amory (2020) 的统计数据支撑。

### 策略 C：增大传感器成本异质性（中高优先级）

**调整内容**：修正传感器功率成本向量，使其更准确地反映真实硬件规格（GMX500:Parsivel²:FC4 ≈ 1:5:0.2），而非当前可能使用的近均等成本。

**物理依据**：根据已确认的真实硬件规格：
- GMX500 MaxiMet：≈ 0.3 W（归一化成本 ≈ 1.0）
- Parsivel²（测量模式）：1.5 W（归一化成本 ≈ 5.0）
- Parsivel²（加热器激活）：50–100 W（归一化成本 ≈ 167–333）
- FC4 FlowCapt：≈ 0.06 W（归一化成本 ≈ 0.2）

**关键洞察**：若当前成本向量中各传感器成本差异较小（如均在 0.8–1.2 之间），则预算约束对不同传感器的选择几乎无差别，动态调度退化为随机选择。引入真实的 1:5:0.2 成本比例后：
- Parsivel² 的高成本使其成为"稀缺资源"，只有在事件期间才值得激活
- FC4 的低成本使其几乎可以"免费"常开，但其信息价值在非事件期间接近零
- 这种成本-价值的非线性关系正是动态调度的用武之地

**具体参数**：
```python
# 修正后的传感器成本向量（基于真实硬件规格）
SENSOR_COSTS_PHYSICAL = {
    'met_station_core':         0.30,   # GMX500, 0.3W
    'radiometer_basic':         0.20,   # 典型辐射计, ~0.2W
    'snow_particle_counter':    0.15,   # 低功耗粒子计数器
    'surface_temp_ir':          0.10,   # IR 温度计, 低功耗
    'ultrasonic_anemometer_hd': 0.40,   # 高精度超声波风速仪
    'shielded_thermo_hygro':    0.12,   # 防辐射温湿度计
    'laser_disdrometer':        1.50,   # Parsivel², 测量模式
    'fc4_flux':                 0.06,   # FC4 FlowCapt, 极低功耗
}
# 归一化后总成本 ≈ 2.83，B=1.70 约束强度 ≈ 60%
```

**预期效果**：
- laser_disdrometer 的高成本（1.50）使其在预算约束下成为关键决策点
- feasible_static_projected 无法同时开启 met_station_core + laser_disdrometer（成本 1.80 > B=1.70）
- PD-PPO 学会在事件期间激活 laser_disdrometer（牺牲其他传感器），在非事件期间关闭它
- 这种"条件性激活"行为正是论文声称的"adaptive scheduling"

### 策略 D：引入预热成本惩罚到奖励函数（中优先级）

**调整内容**：在奖励函数中显式加入预热成本惩罚项，使智能体学会"预测性预热"而非"反应性预热"。

**当前问题**：round_robin 和 AoI 的 warmup_abort_count 极高（1530 和 2700），说明这两个基线频繁触发"预热→事件结束→中止"的无效循环。但 PD-PPO 通过学习"不预热"来规避这个问题，导致其行为看起来"过于保守"。

**调整方案**：在奖励函数中加入预热效率奖励：

```python
def compute_reward(self, action, obs_quality, event_flag, warmup_completed):
    # 原始 oracle reward
    r_oracle = self.prev_mae - self.oracle_mae(obs_quality)
    
    # 预热效率奖励（新增）
    # 如果预热完成且事件发生：正奖励（成功预测并预热）
    # 如果预热中止（事件未发生）：负惩罚（无效预热）
    r_warmup = 0.0
    if warmup_completed and event_flag:
        r_warmup = +self.alpha_warmup   # 建议 alpha_warmup = 0.05
    elif not warmup_completed and action == 'activate_high_latency':
        r_warmup = -self.alpha_warmup * 0.5  # 中止惩罚（较小）
    
    return r_oracle + r_warmup
```

**预期效果**：
- PD-PPO 被激励去学习"在事件预测置信度高时才预热高延迟传感器"
- 这使得 snow_particle_counter 和 laser_disdrometer 的动态行为更加明显
- 与 EventAwareCritic 的设计意图完全一致：利用事件预测来优化预热时机

**注意**：这是对奖励函数的修改，需要重新训练 PD-PPO。如果时间不允许，可以作为消融实验（A3）而非主实验。

### 策略 E：修改 β 权重，提升吹雪传感器的评估权重（中优先级）

**调整内容**：将 FW-MAE 中吹雪相关变量（blowing snow flux, particle size distribution）的权重 β_snow 提升至与气象变量相当的水平。

**物理依据**：论文的核心应用场景是南极吹雪监测，吹雪通量的准确预测对于冰雪质量平衡研究至关重要。若 β_snow 过低，则评估指标与应用目标不一致。

**具体参数**：
```python
# 当前 β 配置（推测）

# 调整后 β 配置（snow_heavy）

    'pressure': 0.08,
    'humidity': 0.08,
    'snow_flux': 0.30,        # 提升至 2×
    'particle_size': 0.30,    # 提升至 2×
}
```

**预期效果**：
- laser_disdrometer 和 fc4_flux 的调度决策对 FW-MAE 的贡献显著增加
- PD-PPO 的动态调度行为（主要集中在这两个传感器）在评估指标中得到体现
- feasible_static_projected 的"固定子集"策略在 snow_heavy 配置下表现更差（因为它无法动态响应吹雪事件）

## 三、推荐的组合调整方案

基于以上分析，推荐以下**两套场景配置**，分别对应不同的论文叙事目标：

### 方案 1：最小改动方案（保守，适合时间紧迫的大修）

**仅执行策略 A + 策略 B**，不修改奖励函数或 β 权重。

| 参数 | 当前值 | 调整后 |

| 预算 B | {1.65, 1.70, 1.75} | 新增 {1.50, 1.55, 1.60} |
| 事件频率 λ_event | 默认（~0.20） | 高频场景：0.40 |
| 成本向量 | 当前设定 | 不变 |
| β 权重 | 当前设定 | 不变 |

**论文叙事**：
> "Under moderate power budgets (B ≥ 1.65), the learned policy converges to a near-static sensor subset, consistent with the theoretical optimality of fixed-priority scheduling when budget constraints are non-binding. Under tighter budgets (B ≤ 1.60) representative of Antarctic polar night conditions, or under elevated blowing snow event frequency (λ ≥ 2×) consistent with Adélie Land winter statistics (Amory, 2020), PD-PPO demonstrates statistically significant advantages over static projection (Wilcoxon, p < 0.05 after Bonferroni correction)."

**预期结果**：
- B=1.50 时：PD-PPO 切换率显著提升（预计 > 1.0/step），feasible_static_projected 被迫切换
- λ=0.40 时：PD-PPO 的 warmup_abort_count 显著低于 round_robin 和 AoI
- 两个条件下 PD-PPO vs static projection 的 Wilcoxon p < 0.05

## 四、关键实施细节与注意事项

### 4.1 feasible_static_projected 必须针对每个新配置重新优化

这是最容易犯的错误。当预算从 B=1.70 收紧到 B=1.50 时，最优固定子集会发生变化。必须对每个 (B, λ_event, cost_vector) 组合重新运行穷举优化，否则 static projection 基线不公平。

```python
# 正确做法：每个配置独立优化
for budget in [1.50, 1.55, 1.60, 1.65, 1.70]:
    for event_rate in [0.20, 0.40]:
        static_policy = optimize_static_projection(
            env_config={'event_rate': event_rate, 'sensor_costs': SENSOR_COSTS_PHYSICAL},
            budget=budget
        )
        # 用这个 static_policy 作为该配置下的基线
```

### 4.2 PD-PPO 需要在新配置下重新训练

策略 A（收紧预算）和策略 B（提高事件频率）改变了环境的状态转移分布，PD-PPO 需要在新配置下重新训练（不能 zero-shot transfer）。建议：
- 在新配置下从头训练 PD-PPO（n=10 seeds，各 500k steps）
- 保留原 V3.1 配置的结果作为"moderate scenario"对比

### 4.3 切换率不是目标，而是结果

论文不应以"PD-PPO 切换更频繁"作为优势声明。切换率是环境约束的函数，不是算法质量的指标。正确的叙事是：
- **在紧预算下**：PD-PPO 的切换是有目的的（事件驱动），而 round_robin 的切换是无目的的（导致高 warmup_abort_count）
- **评估指标**：FW-MAE（最终预测质量）+ warmup_abort_rate（调度效率）+ budget_violation_rate（约束满足性）

### 4.4 "近常量行为"的正确解读

PD-PPO 在宽松预算下学到近静态策略，这本身是一个**有价值的发现**，而非失败。可以这样表述：

> "The convergence of PD-PPO to a near-static policy under non-binding budget constraints (B ≥ 1.65) is consistent with the theoretical result that fixed-priority scheduling is optimal when the budget constraint is inactive (Fernandez-Bes et al., 2025). This confirms that PD-PPO correctly identifies the regime boundary: it behaves as a static scheduler when static scheduling is optimal, and transitions to dynamic scheduling when constraints become binding."

这将"退化"转化为"正确的自适应行为"，是诚实且有说服力的论文叙事。

## 五、优先级排序与执行时间表

| 调整策略 | 预计重训练时间 | 优先级 | 是否需要修改代码 |
|---------|-------------|--------|----------------|
| A：收紧预算 B ≤ 1.60 | 8–12h（重训 PD-PPO） | 最高 | 仅修改配置参数 |
| B：提高事件频率 2× | 8–12h（重训 PD-PPO） | 高 | 仅修改配置参数 |
| C：物理真实成本向量 | 8–12h（重训 PD-PPO） | 高 | 仅修改配置参数 |
| E：snow_heavy β 权重 | 无需重训（仅评估） | 中 | 修改评估脚本 |
| D：预热奖励项 | 16–24h（重训 PD-PPO） | 低 | 修改奖励函数 |

**建议执行顺序**：A + C（同时，因为都只改配置）→ B（独立场景）→ E（评估阶段加入）→ D（如有时间）

A 和 C 可以合并为一次重训：在物理真实成本向量 + B=1.50/1.55/1.60 的配置下训练 PD-PPO，这是最高效的路径。
