# Turn 24：任务一完成后的 Codex Prompt（修复 Oracle 全观测上界一致性）

## 当前状态诊断

任务一（真实 forecast metric 实现）已完成，14 个测试通过，但验收未通过。关键结果如下：

| policy | forecast_weighted_mae_overall |
|---|---:|
| feasible_static_projected | 0.4461 |
| full_open_unconstrained | 0.4577 |
| round_robin | 0.4587 |
| ppo | 0.4811 |
| random | 0.4927 |
| aoi | 0.5051 |

**根本问题**：`full_open_unconstrained`（0.4577）不是 forecast metric 下的最优上界，反而被 `feasible_static_projected`（0.4461）超越。这说明 frozen TCN oracle 在 full_open 输入下的预测性能并不优于部分观测输入，即 oracle 的"全观测上界一致性"被破坏。

**根因分析**：oracle 在训练时虽然包含了 full_open 轨迹（Turn 23 修复），但 oracle 的预测目标是固定的未来 H 步真值，而 `feasible_static_projected` 恰好选择了对 oracle 预测最有利的传感器子集（因为它是静态最优组合，oracle 的训练分布可能与该子集的观测模式更匹配）。换言之，oracle 的泛化能力不足：它在 full_open 输入下的预测误差高于在某个固定子集输入下的误差，说明 oracle 没有学会"更多观测 → 更好预测"的单调性。

**正确的下一步**：不应直接做 PPO warm-start（否则会把 PPO 教向当前 oracle 认为最优的静态策略，而非真正的全观测上界）。应先修复 oracle 的全观测上界一致性，使 `full_open` 在 forecast metric 下成为真正的上界，再验证 PPO 相对于可行基线的排名。

**任务：修复 Oracle 全观测上界一致性**

目标：使 `full_open_unconstrained` 在 `forecast_weighted_mae_overall` 下成为所有策略中的最低值（真正的上界）。

**诊断步骤（先做，再修）**：

1. **检查 oracle 训练数据分布**：读取 oracle 训练脚本（`scripts/23_v2_train_ppo.py` 或 oracle 专用训练脚本），确认 full_open 轨迹在训练 batch 中的实际比例。目标：full_open 应占训练样本的至少 20%（当前可能过低）。

2. **检查 mask 编码**：在 `src/v2/oracle.py` 或 `tcn_oracle.py` 中，确认 oracle 如何处理 mask 输入。若 mask 是拼接到输入特征上的（`[obs, mask]` 拼接），则 full_open 的 mask（全1）与训练时的稀疏 mask 分布差异可能导致泛化问题。

3. **检查 full_open 的 forecast_mae 分布**：在 `forecast_eval.py` 中，输出 full_open 策略下每个变量的 `forecast_mae`，与 `feasible_static_projected` 逐变量对比，找出哪些变量导致 full_open 的整体 MAE 更高。

**修复方案（按优先级）**：

**方案 A（最高优先级）：增加 full_open 样本在 oracle 训练中的比例**

在 oracle 训练脚本中，将 full_open 轨迹的采样权重提高到 30%–40%（当前若低于此值）。具体修改：
- 若 oracle 训练使用 replay buffer 或数据集，在数据生成阶段增加 full_open 策略的轨迹数量
- 若使用事件偏置采样（`multi-start event-biased sampling`），确保 full_open 策略也参与事件时段的采样
- 重新训练 oracle，保存新 checkpoint 到 `checkpoints/oracle_v2_fullopen_balanced/`

**方案 B（若方案 A 不足）：添加单调性正则化损失**

在 oracle 训练损失中添加辅助约束：对同一时步，full_open 输入下的预测误差应 ≤ 任意部分观测输入下的预测误差（期望意义上）。具体实现：
- 在每个训练 batch 中，对同一时步同时生成 full_open 输入和随机部分观测输入
- 添加 hinge loss：`L_mono = max(0, loss_full_open - loss_partial + margin)`，其中 `margin = 0.01`
- 总损失：`L_total = L_pred + lambda_mono * L_mono`，建议 `lambda_mono = 0.1`

**方案 C（若方案 A/B 均不足）：修改 mask 编码方式**

若 mask 编码导致 full_open 输入的分布偏移，考虑以下修改：
- 将 mask 从拼接特征改为乘性门控（`obs_input = obs * mask + mean_fill * (1 - mask)`，不再将 mask 本身作为输入特征）
- 这样 oracle 的输入维度不变，且 full_open 下 mask 全1时输入退化为纯观测值，与部分观测输入在同一特征空间内

**验收标准（修复后）**：
- `full_open_unconstrained` 的 `forecast_weighted_mae_overall` 为所有策略中最低
- `full_open` 与 `feasible_static_projected` 的差距 > 0.01（即上界有意义）
- PPO 的 `forecast_weighted_mae_overall` 低于 `random`、`round_robin`、`aoi`（至少超过这三个朴素基线）

**若修复后 PPO 仍弱于 feasible_static_projected**：记录差距数值，进入 PPO warm-start（任务二，见下方）。

**任务二（条件触发）：PPO warm-start**

仅在 oracle 上界修复后，PPO 在 `forecast_weighted_mae_overall` 下仍弱于 `feasible_static_projected` 时执行。

1. **生成 oracle-greedy 行为克隆数据集**：
   - 对训练集中的每个状态 `s_t`，枚举所有通过 `OnlineSubsetProjector` 的可行动作集合 `A_feasible(s_t)`
   - 对每个可行动作 `a`，用 frozen oracle 计算该动作下的预测误差（即 oracle 的即时奖励信号）
   - 选择误差最小的动作作为 greedy 动作：`a_greedy = argmin_{a in A_feasible} oracle_loss(s_t, a)`
   - 记录 `(s_t, a_greedy_t)` 对，构成 BC 数据集

2. **BC warm-start**：
   - 在 PPO 训练开始前，用 BC 数据集对 PPO actor 网络做 supervised learning（交叉熵 loss），训练 500–1000 步
   - 学习率建议：`1e-4`（低于 PPO fine-tune 阶段的学习率）

3. **PPO fine-tune**：保持现有超参数不变，在 BC warm-start 基础上继续 PPO 训练

4. **对比验证**：输出 warm-start 前后的 `forecast_weighted_mae_overall`，确认 warm-start 有效
