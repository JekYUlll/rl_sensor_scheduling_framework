## 修正四：G1 验证指标——PSD 频率单位改为 cycles/day，KS 验证范围分层

**原始错误 1（PSD 频率单位）**：
- 原文要求 PSD 在 `0.001–0.5 Hz` 范围验证，但 AntAWS 数据步长为 3 小时（`freq_s=10800`），奈奎斯特频率为 1/(2×10800) ≈ 4.6×10⁻⁵ Hz，远低于 0.001 Hz
- 0.001–0.5 Hz 对应秒级采样，与 3 小时步长数据完全不匹配

**修正后的 PSD 验证指标（G1-V4）**：
- 频率单位改为 **cycles/day（cpd）**
- AntAWS 3 小时步长的奈奎斯特频率为 4 cpd（即每天最多 4 个完整周期）
- 验证范围：**0.1–4.0 cpd**（对应 6h–10d 周期，覆盖日变化、天气系统尺度）
- 验证标准：合成风速 PSD 与 AntAWS 参考 PSD 的对数均方误差 < 0.1（在 0.1–4.0 cpd 范围内）

**原始错误 2（KS 验证范围过宽）**：
- 原文要求"所有 8 个传感器通道 KS < 0.05"，但 AntAWS 不提供吹雪粒径、速度、质量通量的真实观测基准，无法对这些通道做 KS 检验

**修正后的 G1 验证指标体系**：

| 指标代号 | 验证对象 | 参考数据来源 | 验证标准 |
|---------|---------|------------|---------|
| G1-V1 | 风速 ACF（lag 1–48h） | AntAWS D17 | 最大绝对偏差 < 0.05（lag 1–12h） |
| G1-V2 | Event fraction 分布 | Amory 2020 D17 统计 | P(ef > 0.75) > 0.05；P(ef < 0.25) > 0.30 |
| G1-V3a | 基础气象变量边际分布（风速、气温、气压、湿度、辐射） | AntAWS D17 | KS 统计量 < 0.05（5 个通道） |

| G1-V4 | 风速 PSD（0.1–4.0 cpd） | AntAWS D17 | 对数均方误差 < 0.1 |

## 修正五：V3 生成器参数来源——软化"来自 Amory 2020 D17"的过实表述

**原始错误**：
- 转移概率矩阵（如 `P(calm→calm)=0.92`）被写成"来自 Amory 2020 D17 站点统计"，但 Amory 2020 仅报告了事件频率（~20%）和中位持续时间（D17 中位 15h），并未直接给出半马尔可夫转移矩阵
- 将手工拟合参数写成文献实测矩阵，会在审稿时被质疑

**修正后的参数来源表述**：

转移概率矩阵和状态持续时间分布参数应表述为"**calibrated to match Amory-reported event frequency and duration statistics**"，而非"来自 Amory 2020"。具体标定逻辑如下：

- **事件频率约束**：Amory 2020 报告 D17 站点 event fraction ≈ 20%。在半马尔可夫模型中，稳态 storm 概率 π_storm 应满足 π_storm × P(event|storm) ≈ 0.20。
- **事件持续时间约束**：Amory 2020 报告 D17 中位事件持续时间 15h。storm 状态的 Weibull 持续时间分布参数应使中位值 ≈ 15h。
- **转移矩阵参数**：通过上述两个约束反推，而非直接从文献读取。

**正文中的表述模板**（`sections/04_simulation_environment.tex`）：

```latex
The semi-Markov transition probabilities and state-duration parameters
are calibrated to reproduce the event frequency (${\approx}20\%$) and
median event duration ($15$\,h at D17) reported by
\citet{Amory2020}, rather than being directly measured from a
transition-count matrix.
```

## 修正六：CRED 逐步 Bernoulli——加入 hysteresis 和最小持续时间约束

**原始错误**：
- 仅用 `event_t = Bernoulli(cred(wind_t))` 会导致事件逐点抖动（每步独立采样），无法生成合理的事件持续时间分布
- G1-V3b 的 event duration 验证很可能因此失败

**修正后的事件触发逻辑**（伪代码）：

```python
# 参数（来自 Amory 2020 D17 标定）
MIN_EVENT_DURATION = 3    # 最小事件持续步数（3h，3 步 × 1h/步）
MIN_GAP_DURATION   = 6    # 最小事件间隔步数（6h）
HYSTERESIS_ON      = 0.6  # 进入事件状态的 CRED 阈值（高阈值，防止误触发）
HYSTERESIS_OFF     = 0.3  # 退出事件状态的 CRED 阈值（低阈值，防止过早退出）

event_state = False
event_duration = 0
gap_duration = MIN_GAP_DURATION  # 初始化为已满足最小间隔

for t in range(T):
    p = cred(wind_speed[t])
    if not event_state:
        # 进入事件：需要 CRED > HYSTERESIS_ON 且满足最小间隔
        if p > HYSTERESIS_ON and gap_duration >= MIN_GAP_DURATION:
            if Bernoulli(p):
                event_state = True
                event_duration = 1
                gap_duration = 0
        else:
            gap_duration += 1
    else:
        # 退出事件：需要 CRED < HYSTERESIS_OFF 且满足最小持续时间
        if p < HYSTERESIS_OFF and event_duration >= MIN_EVENT_DURATION:
            if Bernoulli(1 - p):
                event_state = False
                gap_duration = 1
                event_duration = 0
        else:
            event_duration += 1
    event_indicator[t] = int(event_state)
```

此设计保证：
1. 事件持续时间 ≥ `MIN_EVENT_DURATION`（避免单步闪烁）
2. 事件间隔 ≥ `MIN_GAP_DURATION`（避免连续触发）
3. 进入/退出阈值不对称（hysteresis），使事件边界平滑

**G1-V3b 验证标准不变**（event duration 中位数 ∈ [12h, 20h]），但现在有合理的机制保证该标准可达。

## 修正七：S2 需明确重新训练 oracle 和 PD-PPO

**原始错误**：
- S2 设计未明确说明是否在 V3 生成器上重新训练 oracle 和 PD-PPO
- 若直接将 V2 训练的策略在 V3 环境上评估，则测量的是迁移性能而非 V3 上的最优性能，两者目标不同

**修正后的 S2 实验设计**：

S2 是在 V3 生成器上的**完整重跑**，包括：
1. 重新训练 oracle（在 V3 生成器上运行 oracle 策略，获取 V3 环境下的 oracle 先验）
2. 重新训练 PD-PPO（在 V3 生成器上从头训练，使用 V3 oracle 先验）
3. 重新评估所有基线策略（Full obs.、Static proj.、Round-robin、AoI、Random）

**不应做的事**：将 V2 训练的 PD-PPO 直接在 V3 环境上评估（除非实验目标明确标注为"V2→V3 迁移评估"，作为独立的迁移实验）。

**正文表述**：S2 结果应在 §6 中作为主要结果报告，V2/S1 结果可在附录中保留作为"preliminary results with V2 generator"。

## 修正九：A1-v6 复用 A2 D1 数据的问题——明确不可复用

**原始错误**：
- 原计划写"A1-v6 可直接复用 A2 D1 数据（0.4224 ± 0.0326）"

**修正后的处理方式**：
- A1-v7（MaskedActor only，对应原 A1-v6）必须独立运行 n=10 seeds
- A2 D1 数据（0.4224 ± 0.0326，n=5）可在正文中作为**参考值**引用，并注明"n=5，seeds 41–45，来自 A2 staged diagnostic"
- 正文中不得将 A2 D1 数据直接填入 A1 消融表的 n=10 列
