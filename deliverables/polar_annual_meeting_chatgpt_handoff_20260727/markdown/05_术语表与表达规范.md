# 术语表与表达规范

## 推荐中英文对应

| 中文 | 英文 | 说明 |
|---|---|---|
| 传感器系统调度 | sensing system scheduling | 不简称为“sensing” |
| 传感器通道 | sensor channel of the system | 强调调度对象属于同一系统 |
| 功耗预算 | power budget | 不说“只能使用一种能源” |
| 最小持续开启时间 | minimum activation duration | 不称为 duration constraint |
| 占空比 | duty cycle | 一段时间内通道处于开启状态的比例 |
| 信息年龄 | age of information, AoI | 距离最近一次有效观测的时间 |
| 可行动作掩码 | feasible-action mask | 排除违反硬约束的动作 |
| 固定调度 | fixed schedule | 验证集选择的固定通道组合 |
| 预测驱动调度 | prediction-driven scheduling | 用下游预测损失评价调度 |
| 未来多步预测损失 | multi-step forecast loss | 覆盖多个未来时间步 |
| 事件类型等权归一化损失 | macro-averaged normalized forecast loss | 三类事件分别归一化后等权平均 |
| 预警信号 | warning signal | 含噪声的在线先兆，不是真实事件标签 |
| 冻结预测器 | frozen forecaster | 先拟合后固定的评分模型 |
| 受控仿真 | controlled simulation | 不是现场部署验证 |
| 粒子事件 | particle event type | 粒子微结构信息更重要 |
| 通量事件 | flux event type | 质量通量信息更重要 |
| 热事件 | thermal event type | 雪面热状态更重要 |

## 表达原则

- 首次出现 PD-PPO 时写全称并用一句话解释，不连续堆叠缩写。
- 先讲极地观测问题，再讲算法；不要从 PPO 公式开场。
- 每页标题写成结论句，避免“研究背景”“方法介绍”等空标题。
- 图中尽量使用中文短语，公式和必要算法名保留英文。
- 使用“预测损失更低”“调度更符合事件信息需求”等可验证表述。
- 将“固定调度”解释为验证集上选择的最强固定组合，而不是随意指定组合。
- 将“宏平均”解释为让三类事件在总体评价中获得相同权重。

## 避免的表述

- “所有动态策略都显著优于所有基线。”
- “真实事件标签驱动在线决策。”
- “冻结预测器实时控制传感器。”
- “南极现场实验证明。”
- “完全解决极地观测能源问题。”
- “新型 PPO 算法”或“首个通用传感器调度算法”。
- 内部代号和历史痕迹，例如 V3.1、SCENEBAL、env-dwell12。
- 过度工程化名词，例如 deployment constraints。直接说功耗、启动和持续开启规则。

## PPT 文字风格

- 主标题 28--34 pt，正文 18--22 pt，图注不低于 14 pt。
- 一页不超过 4 个要点，每个要点尽量不超过两行。
- 避免“不是……而是……”“rather than”式反复对照。
- 避免“值得注意的是”“从某种意义上说”等无信息套话。
- 不在正文中堆积小数；主讲页保留一位小数百分比，精确值进入备份页。
